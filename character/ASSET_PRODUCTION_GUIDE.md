# Loaflings 2D 素材生产规范

> 状态：当前生产流程基线
>
> 适用范围：Loafling 角色部件、表情、云朵、换装、道具、孵化阶段、
> 图鉴预览和宣传用完整插画。
>
> 本文规定“如何批量生产和交付素材”。角色长什么样仍以
> `LOAFLING_CHARACTER_SPEC_UPDATED.md` 和 `svg/Pet_Base_Master.svg` 为准；
> 运行时字段、层序和实际可用 ID 以 `modular/manifest.json` 为准。

## 1. 工具职责

### Figma：共享制作与评审工作区

Figma 是 Loaflings 2D 素材的首选共享工作区，用于：

- 保存统一的 `1200 × 900` 制作模板；
- 管理组件、变体、图层、锚点和命名；
- 对比身体、表情、云朵和穿戴组合；
- 设置 SVG 与透明 PNG 导出规格；
- 集中进行视觉评审和修改。

Figma 文件不是唯一交付物。批准后的素材必须导出并提交到仓库；不能只存在于
Figma 中。Figma 文件创建后，应把文件链接和用途记录在本文件或 `WORK_PLAN.md`。

### Figma 更新与游戏同步

以后更新 Loaflings Figma 素材库时，要在同一项工作中对照
`ASSET_LIBRARY_INDEX.md` 和 `modular/manifest.json` 检查新增、修改及删除的组件。
确认用于游戏的素材须同步导出到仓库，并接入对应的运行时入口：换装、孵化外观、
图鉴、成长阶段等；涉及名称时同时维护中文和英文。不能只在 Figma 里看到新组件，
却把游戏里的同步视为完成。

完成前须检查素材文件、manifest/配方及游戏页面的实际显示，运行相关测试并在
桌面尺寸检查组合效果，然后更新素材库索引和 `WORK_PLAN.md`。尚属草稿、用途未
确认或暂时无法接入游戏的项目，要明确记录为“未同步”，不能标为已完成。
素材库同步不自动改变孵化概率、角色核心身份或其他玩法规则；这些按用户要求和
现有游戏合同处理。

### AI 图像生成：概念探索和批量候选

AI 图像生成适合：

- 一次探索一组帽子、服装、花纹或情绪方向；
- 生成完整角色穿戴预览；
- 提供水彩质感、配色和轮廓灵感；
- 为宣传插画和场景图提供候选。

生成结果默认是**候选稿**，不是自动批准的运行时素材。候选稿必须按照标准几何、
锚点、透明度和小尺寸可读性重新检查。不要让每次生成重新定义身体、脸或云朵。

### 仓库：运行时交付与版本权威

批准后的运行时素材存放在：

- `character/modular/`：成人角色可组合 SVG；
- `character/png/`：蛋、孵化阶段、复杂水彩效果和 PNG 回退；
- `character/modular/manifest.json`：画布、锚点、层序、兼容性与可用 ID；
- `reference/`：视觉感觉和探索参考，不自动成为需求。

## 3. 画布、坐标与锚点

- 所有可组合素材使用 `1200 × 900` authoring space。
- SVG 必须保留 `viewBox="0 0 1200 900"`。
- 可组合部件保留完整画布，不能单独紧裁切后依靠运行时猜位置。
- 中心轴为 `x = 600`；标准底线为 `y = 675`。
- 锚点坐标以 `modular/manifest.json` 为准，不在 Figma 中维护第二套冲突数值。
- 不同身体对脸、帽子和云朵的细调使用 manifest 中的 transform，不为每个身体复制
  一套几乎相同的部件。
- 云朵必须与身体保持清晰空气间隙；帽子需要抬高云朵时，用 `cloudOffset` 描述。

当前核心锚点：

| Anchor | 坐标 | 用途 |
|---|---:|---|
| `bodyCenter` | `(600, 500)` | 身体整体变换中心 |
| `baseline` | `(600, 675)` | 地面和阴影对齐 |
| `faceCenter` | `(600, 530)` | 表情与面部配饰 |
| `pawLeft` | `(421, 619)` | 左前爪和道具遮挡 |
| `pawRight` | `(779, 619)` | 右前爪和道具遮挡 |
| `tail` | `(885, 585)` | 尾巴和后置物件 |
| `headwear` | `(600, 315)` | 帽子基准点 |
| `cloudCenter` | `(600, 155)` | 云朵中心 |

## 4. 组件和命名规则

Figma 组件名、导出文件名和 manifest ID 应尽量一一对应。使用稳定的英文小写
snake_case，不使用空格、中文文件名、`final2` 或日期作为运行时 ID。

| 槽位 | 前缀 | 示例 |
|---|---|---|
| 身体 | `body_` | `body_classic` |
| 表情 | `expr_` | `expr_happy` |
| 云朵 | `cloud_` | `cloud_rainy` |
| 花纹 | `marking_` | `marking_patchy` |
| 帽子 | `hat_` | `hat_knit_blue` |
| 眼镜 | `glasses_` | `glasses_round_cocoa` |
| 服装 | `outfit_` | `outfit_vest_sage` |

规则：

- 同一概念只保留一个稳定 ID；显示名称可以翻译，ID 不随文案变化。
- `none` 表示空槽，不制作透明占位文件。
- 新素材先检查 ID 是否已存在，再写入 manifest。
- 表情只包含眼睛、嘴、可选腮红和极小情绪符号。
- 云朵素材不包含身体和脸；帽子素材不包含角色头部；衣服素材不烘焙身体颜色。
- 若衣服需要自然遮挡，可拆成前/后层；没有遮挡需求时不要人为增加层数。

## 5. 标准图层顺序

当前成人运行时从后到前：

1. `shadow`
2. `tail`
3. `body`
4. `marking`
5. `outfit`
6. `expression`
7. `facewear`
8. `pawsForeground`
9. `headwear`
10. `cloudMood`

Figma 的组合检查页必须使用相同顺序。若未来引入 `backItem`、前后分离服装或
`heldItem`，必须先更新 manifest 和运行时层序，再将其视为正式槽位。

## 6. 模块化优先，禁止穷举完整组合

不要为每种“身体 × 表情 × 云朵 × 帽子 × 眼镜 × 服装”组合绘制完整 PNG。

完整角色图只用于：

- 概念探索；
- 穿戴比例评审；
- 图鉴封面、活动图和宣传插画；
- 复杂且明确不需要换装的特殊画面。

运行时素材应是独立部件，由 `CharacterAppearance` 配方组合。新增一顶帽子应自动
服务于所有兼容身体，而不是复制出多个整图。身体颜色优先使用调色板、变量或蒙版，
不为同一身体的每种颜色复制完整角色。

## 7. 批量生产流程

每一批素材遵循以下顺序：

1. **定义批次**：只选择一个素材家族，例如帽子或云朵，不混合多个未定方向。
2. **读取规范**：检查角色规范、标准 SVG、相关参考和现有 manifest。
3. **概念板**：一次产生多个候选，保持同一身体、视角、画布和光照。
4. **选择方向**：先批准少量候选；未批准设计不进入正式库。
5. **制作独立部件**：删除身体等无关内容，落到统一透明画布和锚点。
6. **组件化**：建立稳定 ID、槽位、标签、兼容身体、冲突和可重着色信息。
7. **组合检查**：至少在 Classic、Chubby、Long 三个基础身体上测试。
8. **小尺寸检查**：在桌面实际显示尺寸确认轮廓、表情和遮挡仍可读。
9. **导出与接入**：导出到仓库，更新 manifest、预览器和必要测试。
10. **记录批准结果**：在 `WORK_PLAN.md` 记录批次、验证方式和未采用方向。

## 8. 建议的第一批扩展规模

以下数字是**制作规划基线，不是已承诺的游戏内容或一次性生成要求**。每一类都应分批
评审，避免未经检查的大量低质量素材进入项目。

| 类别 | 建议累计目标 | 备注 |
|---|---:|---|
| 基础身体 | 5–8 | 保留软面团视觉 DNA，不变成普通动物 |
| 表情 | 12 | 先覆盖当前 8 个核心表情，再谨慎扩展 |
| 云朵状态 | 12 | 保持干净外轮廓和较小体量 |
| 身体颜色/花纹 | 10 | 优先变量、调色板和遮罩 |
| 帽子 | 16 | 控制高度，并声明云朵偏移 |
| 眼镜/面部配饰 | 8 | 不遮住小眼睛和嘴 |
| 服装 | 16 | 低覆盖率，不能压过角色本体 |
| 小道具 | 8 | 确认后再建立正式运行时槽位 |
| 孵化特效 | 6 | 可使用透明 PNG，不参与成人换装组合 |

## 9. 导出规则

### SVG

成人可组合部件优先使用 SVG：

- 保留 `viewBox="0 0 1200 900"`；
- 背景完全透明；
- 不包含制作参考、网格、标尺、隐藏草稿或外部位图链接；
- 尽量保持可编辑路径，避免无意义的复杂蒙版和巨大路径数量；
- 颜色、描边和 ID 遵循角色规范；
- 导出后必须通过 XML 解析和真实运行时组合检查。

### PNG

蛋、孵化阶段、水彩效果和复杂完整插画可以使用 PNG：

- 需要透明时使用 RGBA；
- 可组合画布从同一标准坐标导出，默认 `2400 × 1800` 的 2× 透明图；
- 使用 sRGB，避免不同电脑出现明显色偏；
- 不保留白底、灰底、棋盘格或软件预览背景；
- 最终运行时尺寸仍需检查边缘、透明像素和缩小时的清晰度。

### 不应作为运行时资产的格式

- JPG 不用于需要透明背景的角色和部件；
- Figma `.fig` 文件不代替仓库中的 SVG/PNG 交付；
- AI 生成的带背景预览图不直接改名后投入运行时。

## 10. 每个素材的 manifest 信息

正式部件至少记录：

```json
{
  "id": "hat_knit_blue",
  "slot": "headwear",
  "src": "headwear/hat_knit_blue.svg",
  "anchor": "headwear",
  "compatibleBodies": ["body_classic", "body_chubby", "body_long"],
  "cloudOffset": { "x": 0, "y": -36 },
  "recolorable": true,
  "tags": ["cozy", "winter", "common"]
}
```

只有在真实需要时才增加 `conflicts`、稀有度、季节、前后层或特殊 transform。不要为
尚未实现的系统预先发明字段。

## 11. 验收清单

### 视觉身份

- [ ] 仍然是软面团般的 Loafling，而不是普通动物或动作游戏角色。
- [ ] 脸极简，眼睛和嘴保持很小。
- [ ] 云朵明显悬浮、比身体小，并保持空气间隙。
- [ ] 颜色柔和、轮廓不使用粗重纯黑线。
- [ ] 配饰不会压过身体、脸和云朵的视觉身份。

### 模块和兼容性

- [ ] 更换一个槽位时，其他槽位不被重新生成或改变。
- [ ] 素材使用标准画布、锚点、命名和层序。
- [ ] 穿戴至少在所有声明兼容的身体上通过组合检查。
- [ ] 服装、前爪、眼镜、帽子和云朵的遮挡关系正确。
- [ ] 未批准的完整概念图没有被误当作模块资产。

### 文件和运行时

- [ ] SVG 可解析且保持 `1200 × 900` viewBox。
- [ ] PNG 尺寸、RGBA 透明度和色彩空间正确。
- [ ] 文件存在于 manifest 声明的位置，ID 不重复。
- [ ] `preview.html` 或等价检查页可以成功组合新素材。
- [ ] 桌面实际显示尺寸可读，缺失素材时仍有安全回退。
- [ ] 自动化测试、截图检查和 `git diff --check` 通过后才记录完成。

## 12. 权威顺序与变更边界

发生冲突时使用以下顺序：

1. 用户当前明确指令；
2. `LOAFLING_CHARACTER_SPEC_UPDATED.md`；
3. `svg/Pet_Base_Master.svg`；
4. `modular/manifest.json` 中已实现的运行时合同；
5. 本生产规范；
6. Figma 工作文件；
7. `reference/` 和 AI 概念图；
8. 制作者个人判断。

Figma、参考图或生成结果不能单独改变角色核心身份、运行时字段或孵化逻辑。新的身体、
槽位、稀有度或生成规则需要单独确认；不要因为素材存在就自动把它加入游戏。
